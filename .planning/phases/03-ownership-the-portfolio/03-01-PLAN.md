## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → Server Action | activityId / workflowId / versionId / activityIds[] arrive from the browser; untrusted |
| browser → Supabase Realtime | client subscribes to activity:<userId> / runs:<workflowId> channels |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-01-01 | Spoofing/Elevation | revertActivity / bulkRevertActivity | mitigate | Filter activity_entries WHERE user_id = userId before canRevert; cross-user IDs silently excluded (Phase 2 approval-ownership pattern) |
| T-3-01-02 | Spoofing | runNow | mitigate | Ownership SELECT on workflows WHERE id+user_id before inngest.send; reject if not found |
| T-3-01-03 | Spoofing | restoreVersion | mitigate | Verify both workflow_id AND user_id on the version lookup before createWorkflowVersion |
| T-3-01-04 | Information Disclosure | Realtime activity:/runs: channels | mitigate | Migration 0005 RLS: activity:<userId> verifies userId==auth.uid(); runs:<workflowId> EXISTS subquery on workflow_runs by user_id |
| T-3-01-05 | Tampering | canRevert bypass via direct Server Action call | mitigate | Server Action re-evaluates canRevert independently of the UI (re-fetches shopify_updated_at fresh) — never trust client |
| T-3-01-SC | Tampering | npm install @tanstack/react-virtual | mitigate | [ASSUMED] package — slopcheck blocking-human checkpoint in plan 03-04 (the plan that installs it) before install |
</threat_model>
