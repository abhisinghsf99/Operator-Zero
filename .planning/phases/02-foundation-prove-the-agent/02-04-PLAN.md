<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Gmail OAuth callback | state is user-controlled (CSRF surface) |
| stored Gmail tokens → Google API | access + refresh tokens must be encrypted at rest |
| Gmail thread content → classifier prompt | email body is untrusted (prompt-injection surface) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-04-01 | Spoofing | Gmail OAuth state | mitigate | State nonce verified in callback before token exchange |
| T-2-04-02 | Information Disclosure | stored access + refresh tokens | mitigate | encryptToken (libsodium) on both tokens; never logged in plaintext |
| T-2-04-03 | Tampering | prompt injection via email body in classifier | mitigate | Classifier prompt asks only for a YES/NO label; email content is data, not instructions; output is coerced to a boolean (no tool access) |
| T-2-04-04 | Information Disclosure | cross-user thread leakage | mitigate | serviceDb queries always filtered by user_id; gmail mirror tables RLS-enabled |
</threat_model>
