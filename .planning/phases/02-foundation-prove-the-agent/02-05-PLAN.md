<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM tool call → tool execute | tool inputs are model-generated, untrusted |
| store/email content → prompt | mirror data may contain injected instructions |
| user → daily LLM spend | runaway cost is a DoS / financial risk |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-05-01 | Tampering | tool inputs from the model | mitigate | Zod safeParse in dispatchTool; invalid input returns a correctable tool_result, never executes |
| T-2-05-02 | Denial of Service | unbounded LLM spend | mitigate | AUTH-07 checkCostCap before every LLM call; hard cap disables write tools; AUTH-06 rate limit upstream |
| T-2-05-03 | Tampering | prompt injection via Shopify product HTML | mitigate | Raw user HTML is not injected as instructions; store context is summarized/escaped into a data section of the prompt |
| T-2-05-04 | Information Disclosure | cross-user memory recall | mitigate | recallMemory + all tool queries filter by user_id (serviceDb RLS-bypass requires explicit filter) |
| T-2-05-05 | Elevation | write tool executes without approval | mitigate | approvalRequired gate keyed on automation level; engine (02-07) enforces L1/L2/L3 before execute |
</threat_model>
