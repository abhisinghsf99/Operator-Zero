<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Inngest job → all user tables | export/purge run with serviceDb (RLS-bypassing); userId from event payload must scope every query |
| Storage bucket → download | export object must never be public; only time-limited signed URL |
| client → delete action | deletion is destructive + must be blocked mid-run and cancellable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-05-01 | Information Disclosure | export bundling another tenant's data | mitigate | every serviceDb query in the export job filters by `eq(table.user_id, userId)`; userId from event payload only |
| T-4-05-02 | Information Disclosure | export object public exposure | mitigate | private `user-exports` bucket; download via 24h `createSignedUrl` only — never a public object URL |
| T-4-05-03 | Tampering / DoS | delete while a run is mid-execution | mitigate | requestAccountDeletion gate blocks on running/paused_for_approval; lock step aborts active runs (Pitfall 4) |
| T-4-05-04 | Tampering | purge orphaning/leaking other tenants' data | mitigate | hard-delete via auth.users cascade scoped to userId; Storage cleanup scoped to `exports/${userId}/` only |
| T-4-05-05 | Tampering | wrong-account cancel via CEL inversion | mitigate | cancelOn `if: "async.data.userId == event.data.userId"` (Pitfall 7) — never event==event |
| T-4-05-06 | Tampering | non-idempotent retry double-delete crash | mitigate | hard-delete try-catch ignores "not found" (idempotent) |
</threat_model>
