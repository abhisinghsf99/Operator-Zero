<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → Server Action | snooze/edit/bulk/revert inputs are untrusted; cross-tenant mutation risk |
| Server Action → Inngest engine | edited proposed_action must be read from DB by the engine, not trusted from event payload |
| browser → Supabase Realtime | postgres_changes subscription must respect RLS (no cross-tenant leakage) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-02-01 | Tampering | snoozeItem/editItem/bulkResolve/revertApproved | mitigate | (id + user_id) ownership re-check before every write (PATTERNS pattern 2) + RLS; Zod validation on all inputs |
| T-4-02-02 | Tampering | editItem edited payload | mitigate | edited proposed_action written to DB row; engine reads from DB row not event (T-2-07-02 invariant) |
| T-4-02-03 | Elevation of Privilege | snooze resuming a paused run | mitigate | snoozeItem MUST NOT fire approval.resolved; run stays paused until explicit approve (A1) |
| T-4-02-04 | Information Disclosure | Realtime postgres_changes | mitigate | filter `user_id=eq.${userId}` + approvals RLS SELECT policy (migration 0003) gates the subscription |
| T-4-02-05 | Tampering | bulkResolve race (re-resolve already-resolved) | mitigate | atomic update WHERE status='pending'; non-pending ids silently skipped, not errored |
| T-4-02-06 | Spoofing | approve drifted item without seeing change | mitigate | D-03 drift banner + re-confirm; no one-tap approve on stale items |
</threat_model>
