<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server Action → workflow engine | autonomy override must be enforced in the engine, not trusted from client |
| login request → session registry | UA/IP are client-influenced; stored as labels only, never as a trust decision |
| client → revoke action | revoking another user's session must be impossible |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-04-01 | Elevation of Privilege | autonomy override loosening a gate | mitigate | one-directional logic in execute-workflow-run.ts: override chosen only when strictly more restrictive (D-06); unit test asserts never-loosen |
| T-4-04-02 | Tampering | override enforced in dispatchTool vs engine | mitigate | gate lives in execute-workflow-run.ts (D-07b) consistent with Phase 2 invariant — engine enforces, not dispatchTool |
| T-4-04-03 | Information Disclosure | cross-tenant session list/revoke | mitigate | listSessions/revokeSession filter by user_id + (id+user_id) ownership re-check; RLS on user_sessions |
| T-4-04-04 | Elevation of Privilege | session revoke bypass via still-valid JWT | accept | documented Supabase ~15-min access-token window; revoke refresh token immediately + label honestly; do not claim instant |
| T-4-04-05 | Tampering | injected override key (non-curated tool) | mitigate | Zod restricts override keys to the D-05 curated tool set before persist |
| T-4-04-06 | Spoofing | forged session row via UA/IP | mitigate | UA/IP stored as display labels only; user_id from claims.sub; supabase_session_id correlates the real session |
</threat_model>
