## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] FK to auth.users not generated by drizzle-kit**
- **Found during:** Task 3 (reviewing generated SQL)
- **Issue:** `drizzle-kit generate` cannot emit REFERENCES `auth.users(id)` because the `auth` schema is outside Drizzle's schema scope. Generated SQL had no FK.
- **Fix:** Added FK REFERENCES auth.users(id) ON DELETE CASCADE manually to `0001_initial_schema.sql` for both `user_profiles.user_id` and `integrations.user_id` per DATA-FLOW §2.1/§2.2 requirements.
- **Files modified:** supabase/migrations/0001_initial_schema.sql
- **Commit:** 3b882b9

**2. [Rule 2 - Missing Critical] Test isolation: DB client threw at import time**
- **Found during:** Task 2 GREEN verification (running vitest without DB env)
- **Issue:** `lib/db/client.ts` called `resolveDbConfig()` at module import time. Any test that imported `@/lib/db/client` (including the schema tests) would throw `NEXT_PUBLIC_SUPABASE_URL is not set` unless all DB env vars were present. This broke `npx vitest run` without env prefix.
- **Fix:** Added stub env vars to `vitest.config.mts` test.env section (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SERVICE_ROLE_KEY` as non-real test stubs). This allows the DB layer to be imported in unit tests without a live DB.
- **Files modified:** vitest.config.mts, lib/db/client.ts
- **Commit:** 590ec3d

**3. [Rule 3 - Blocking] Drizzle symbol introspection API discovery**
- **Found during:** Task 2 GREEN (schema test implementation)
- **Issue:** Tests used `table._columns` (non-existent) instead of the actual Drizzle internal Symbol API. The column access pattern is `table.user_id` directly (columns are on the table object), not via `_.columns`. RLS and extra config (policies, indexes, unique constraints) require `Symbol.for('drizzle:EnableRLS')` and `Symbol.for('drizzle:ExtraConfigBuilder')`.
- **Fix:** Investigated actual Drizzle 0.45.2 object structure via node REPL; rewrote tests to use the correct Symbol-based introspection. Also discovered `ExtraConfigColumns` (not `Columns`) must be passed to ExtraConfigBuilder when calling `index().on()` to avoid `JSON.parse(undefined)` error.
- **Files modified:** tests/unit/schema.test.ts
- **Commit:** 4c11903

**4. [Rule 1 - Bug] TypeScript noUncheckedIndexedAccess on Buffer index**
- **Found during:** Task 1 GREEN (tsc check)
- **Issue:** `buf[buf.length - 1] ^= 0xff` fails strict type check because `noUncheckedIndexedAccess` makes the indexed access `number | undefined`.
- **Fix:** Added bounds guard `if (lastIdx >= 0) buf[lastIdx] = (buf[lastIdx] ?? 0) ^ 0xff`
- **Files modified:** tests/unit/crypto.test.ts
- **Commit:** 4c11903 (bundled with GREEN commit)
