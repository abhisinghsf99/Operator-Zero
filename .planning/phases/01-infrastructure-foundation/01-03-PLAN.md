helloWorld = inngest.createFunction(
  { id: 'hello-world', concurrency: { limit: 1, key: 'event.data.userId' }, retries: 3 },
  { event: 'dev/hello.world' },
  async ({ event, step }) => {
    const r1 = await step.run('checkpoint-1', async () => ({ checkpointed: true, userId: event.data.userId }))
    const r2 = await step.run('checkpoint-2', async () => ({ finished: true, from: r1 }))
    return r2
  })

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Inngest cloud -> serve route | Incoming function-invocation requests must be authentic |
| agent tier -> Anthropic/Voyage | Server-only API keys must never reach the browser |
| user -> chat send (future) | Per-user request volume must be capped to prevent runaway cost |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-03-01 | Tampering | Inngest serve route | mitigate | INNGEST_SIGNING_KEY verifies invocation requests (Inngest serve validates the signature); never disabled in deployed envs |
| T-1-03-02 | Info Disclosure | ANTHROPIC_API_KEY / VOYAGE_API_KEY | mitigate | Server-only env vars (no NEXT_PUBLIC_); referenced only in lib/agent/*; Task 2 acceptance greps for absence of NEXT_PUBLIC_ on these |
| T-1-03-03 | Denial of Service | Runaway LLM cost | mitigate | Per-user rate limit (AUTH-06, lib/rate-limit.ts) + Inngest concurrency key { limit: 1, key: 'event.data.userId' } serializing per-user durable runs |
| T-1-03-04 | Spoofing | Adapter skeletons performing real ops prematurely | accept | Skeletons return false / throw 'Not implemented until Phase 2'; no tokens read, no external calls in Phase 1 — no live attack surface |
</threat_model>
