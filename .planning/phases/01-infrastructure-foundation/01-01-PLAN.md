<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo -> npm registry | Third-party package installs cross into the build (supply-chain) |
| browser -> Sentry/Axiom | Client init must not leak server-only secrets |
| CI -> Vercel/Sentry | Build-time secrets (SENTRY_AUTH_TOKEN) must stay in CI/secret store |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-01-SC | Tampering | npm installs (all [ASSUMED] packages) | mitigate | Task 1 blocking-human legitimacy gate verifies every package against npmjs.com publisher/repo before the first install; never auto-approvable |
| T-1-01-01 | Info Disclosure | Sentry browser init / .env | mitigate | Only NEXT_PUBLIC_* exposed to the browser; SENTRY_AUTH_TOKEN is CI-only; .env.local gitignored (verified in Task 3 acceptance) |
| T-1-01-02 | Info Disclosure | CI workflow secrets | mitigate | SENTRY_AUTH_TOKEN read from GitHub/Vercel secret store, never inlined in ci.yml |
| T-1-01-03 | Tampering | Health route ?testError trigger | accept | Health route only throws a benign captured error; no state mutation, no PII; acceptable for a smoke endpoint |
</threat_model>
