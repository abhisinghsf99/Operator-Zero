# Quick Task 260526-v0o — Stamp integrations.last_synced_at on Shopify full sync

## Problem

The Settings → Connections badge shows Shopify as **"stale / never synced"** even right after a
successful connect + catalog sync. Root cause: `shopifyFullSyncForUser()` in
`lib/integrations/shopify/sync.ts` stamps `last_synced_at` on products/variants/orders/pages/
redirects and updates the separate `shopify_sync_state` table, **but never updates the
`integrations` row's `last_synced_at`**. The health classifier (`lib/integrations/health.ts`,
`getIntegrationHealth`) reads exactly `integrations.last_synced_at`: `active` + `null` → "stale
(never synced)". So a working sync leaves the badge stale.

## Task (single, code-only)

In `lib/integrations/shopify/sync.ts`, at the END of `shopifyFullSyncForUser(userId)` — right
after the `shopifySyncState` upsert (the block that sets `last_full_sync_at` / `sync_status:
"healthy"`, ~line 400), before/around the final `full_sync_complete` console.log — ADD:

```ts
// Stamp the integration row so health (getIntegrationHealth) reads a fresh sync time.
await serviceDb
  .update(integrations)
  .set({ last_synced_at: now, last_error: null })
  .where(and(eq(integrations.user_id, userId), eq(integrations.provider, "shopify")));
```

- `integrations`, `serviceDb`, `eq`, `and` are already imported; `now = new Date()` is at the top
  of the function. Add imports only if genuinely missing.
- Do NOT modify the product/order/page/redirect loops or the `shopify_sync_state` update.
- Fixes the 5-min poll path too (`shopifyIncrementalSyncForUser` delegates to the full sync).

**verify:** `npx tsc --noEmit` passes.
**done:** `integrations.last_synced_at` is set after a full sync; badge resolves to healthy.
