domain BEFORE redirecting to `/api/integrations/shopify/connect`. The server route

otherwise. Today both client surfaces redirect with no shop param, so connect always errors.

Purpose: Make the Shopify connect/reconnect flow actually build a valid OAuth init URL.

flow are all out of scope and must NOT change.
Output: A shared client-side normalize/validate helper, an inline domain prompt in the
shared onboarding ConnectStep (Shopify only), and a Radix Dialog domain prompt in Settings
connections (Shopify provider only). Gmail keeps its direct redirect untouched.
</objective>
