<decisions>
D-1 (WS7.13, chat write-tool gating): the chat toolset exposes read tools, meta tools, and ONLY
propose-safe write tools (proposeSafe === true — the three optimize/propose smart tools). Rationale:
the chat route hardcodes automationLevel "L2" and dispatchTool deliberately does not enforce
approval, so any other write tool would hit Shopify/Gmail with no card. The propose-safe tools
return a generated proposal at L2 without writing, which is exactly the demo behavior we want.
Anything requiring a real write must go through propose_workflow_plan → Save as workflow → Run.

D-2 (WS12, ask_user_clarification): the tool stays in the registry for the workflow path but is
EXCLUDED from the chat toolset. The route only renders workflow_plan and preview inline blocks, so
a clarification tool call is a dead end. The prompt guardrails (plan 1) already tell the agent to
ask clarifying questions in plain text.

D-3 (WS7.9, stale streaming rows): reaped server-side in listMessages rather than by a cron —
one UPDATE on thread open, no new infrastructure, and the fix is visible immediately on reload.
</decisions>
