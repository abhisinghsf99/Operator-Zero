# Phase quick-260531-w26 Plan 01: Meta Fence Parsing + Restock changeFromQuantity Summary

## One-liner

Replaced content-deleting fence regex in parseMeta with a 3-strategy balanced-JSON extractor; added `changeFromQuantity` sourced from live `on_hand` to `inventorySetOnHandQuantities`, fixing both live-write bugs.

## What Was Built

### Task 1: Robust parseMeta (BUG C)

**Root cause:** `parseMeta` called `text.replace(/```[\s\S]*?```/g, "")` which deleted the entire fenced block including the JSON inside it. When Groq wrapped its response in ` ```json ... ``` `, the JSON was erased before `JSON.parse` ran, yielding empty strings and the "Generated meta was empty after parsing" throw.

**Fix:** Rewrote `parseMeta` in `lib/agent/generation/optimize-meta.ts` with a 3-strategy parser:
1. **PRIMARY** — extract the first balanced `{…}` JSON substring (`indexOf("{")` to `lastIndexOf("}"`), `JSON.parse`, read keys. Handles bare JSON, JSON with preamble, and fenced JSON (the object braces survive regardless of surrounding fence markers).
2. **FENCE-STRIP** — strip only the opening ```` ```lang ```` and closing ```` ``` ```` delimiter lines preserving inner text, retry `JSON.parse`. Belt-and-suspenders for edge cases where strategy 1 cannot extract a balanced object.
3. **LINE-BASED** — existing fallback: first non-empty line → title, remaining lines joined → description.

HTML-tag strip and ≤60/≤160 SEO length guards preserved. `tryExtract` helper typed as `Record<string, unknown>` narrowed with `typeof === "string"` (no `any`).

### Task 2: updateInventory changeFromQuantity (BUG D)

**Root cause:** `inventorySetOnHandQuantities` (Shopify API 2024-10) requires `changeFromQuantity` per `setQuantities` entry for compare-and-set semantics. The mutation was called without it, causing a Shopify userError throw and leaving inventory stuck at 0 with `after_state null`.

**Fix:** Extended `updateInventory` in `lib/integrations/shopify/mutations.ts`:
1. Widened the `GetVariantInventory` GraphQL query to include `quantities(names: ["on_hand"]) { name quantity }` on the level node.
2. Extended the typed response: level node is now `{ location: { id: string }; quantities: Array<{ name: string; quantity: number }> }` (strict, no `any`).
3. Computed `currentOnHand` via optional-chaining + `?? 0` fallback.
4. Added `changeFromQuantity: currentOnHand` to the single `setQuantities` entry.

All `quick-260531-vhh` behavior preserved: ID/location resolution, enable-tracking when `tracked:false`, `userErrors` throws on every mutation, re-read + upsert + `backfillAfterState`, `writeActivity`-before-effect ordering, idempotency key, `MutationResult` shape, public signatures, multi-tenant `user_id` scoping.
